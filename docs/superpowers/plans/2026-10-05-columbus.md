# Columbus: ramp-up, discovery map, and companion

Goal: succeed fast in a new company. Three faces of one system, all backed by the single second-brain vault on the new machine.

1. **Ramp up** a new codebase quickly, and be able to ask questions about what was learned.
2. **Discover the system as a map** that starts in fog and lights up as you explore (zoomed world, domain, service, and request-flow levels).
3. **Companion**: the second brain reminds you of open questions, commitments, what is new on the map, and glossary terms to review, at session start.

Decisions (from the design chat): one vault on the new computer; Obsidian Canvas for the map; visuals = fog-of-war map, zoom levels, people graph; companion brief at session start; skill name `columbus`; ramp-up is a mode inside `columbus`; `second-brain` is extended, not forked.

## What will be built

### Single source of truth: typed wiki pages

Every fact lives in a `wiki/<Name>.md` page with Obsidian properties (YAML frontmatter). Maps, tables, and the brief are generated from these pages and are never the source of truth.

The contract lives in `second-brain/references/typed-pages.md` (versioned with dotfiles, so it updates on every rebuild; the vault itself is only seeded once). The vault `schema/AGENTS.md` points to it.

| Type | Purpose | Key properties |
|---|---|---|
| `domain` | Business area, top zoom level | `owners` |
| `service` | Deployable unit | `domain`, `owners`, `calls`, `emits`, `reads`, `writes`, `maybe` |
| `component` | Module inside a service | `parent`, plus the service edge keys |
| `datastore` | DB, queue, topic, bucket | `domain`, `kind` |
| `external` | Third-party or other-org system | `domain` (optional) |
| `flow` | One request traced end to end | `domain`, `steps` (`"[[A]] -> [[B]]: label"`) |
| `repo` | Ramp-up facts for a repository | `implements`, `build`, `test`, `run`, `entry_points` |
| `person` | Who is who | `team`, `role`, `owns`, `ask_about`, `met` |
| `concept` | Glossary term | `aka` |
| `question` | Open unknown | `status` (open/answered), `ask`, `about`, `raised` |
| `commitment` | Something you promised | `status` (open/done), `to`, `due`, `about` |

Map places (`domain`, `service`, `component`, `datastore`, `external`, `flow`) plus `repo` and `concept` carry `knowledge`: `rumored` → `seen` → `understood` → `owned`. Promotion needs evidence in `sources` (`repo:`, `doc:`, `meeting:`, `pr:`, `chat:`); `owned` needs a `pr:` source. `maybe` lists relationships that were heard about but not verified. Links to pages that do not exist yet are drawn as fog.

Company-data rule: the vault stores paths, names, and short explanations, never copied source code or secrets.

### Visuals (generated into the vault)

- `maps/world.canvas`: domains and externals, aggregated cross-domain edges, legend, and an "explored N%" counter.
- `maps/domain-<slug>.canvas`: one group per domain with its services, datastores, and externals, plus foreign neighbors.
- `maps/service-<slug>.canvas`: a service's components plus its direct neighbors.
- `maps/flow-<slug>.canvas`: a request flow, left to right, with numbered steps.
- `maps/people.canvas`: people linked to what they own and what to ask them about.
- `bases/People.base`, `bases/Open loops.base`: Obsidian Bases tables for people/ownership, open questions, and commitments.
- Obsidian graph view color groups by `type` (seeded `.obsidian/graph.json`).

Colors follow knowledge: rumored gray, seen cyan, understood green, owned yellow. Unverified edges are gray with a `?` label. Re-rendering keeps node positions you dragged by hand.

### Code

All scripts are stdlib-only Python 3.9+ (the macOS system interpreter; no PyYAML dependency). Frontmatter uses a documented YAML subset: scalars, quoted scalars, block lists, and `[]`.

- `second-brain/scripts/vault.py`: load and validate typed pages (shared library).
- `second-brain/scripts/brief.py`: the companion brief. `brief.py` prints it on demand; `brief.py --hook` is the Cursor `sessionStart` hook, which injects the brief at most once per day and always fails open (`{}`).
- `columbus/scripts/render_maps.py`: renders all canvases from the typed pages; `--check` validates pages without writing.
- Unit tests next to each script, run with `python3 -m unittest`.

### Skills

- `second-brain` (extended): typed-page contract, a fifth op `brief`, and the rule that typed pages follow the contract.
- `columbus` (new), modes:
  - `survey`: ramp up on a repo (build/test/run, entry points, services it implements, rumored neighbors, glossary, questions for owners).
  - `chart`: file observations from meetings or chat (people, questions, commitments, new places, relationships).
  - `trace`: trace one request through the code into a `flow` page, promoting the places it proves.
  - `ask`: answer ramp-up questions from the vault first, then from code, and file what was learned.
  - `render`: regenerate maps and report the map delta.

### Machine wiring

- New skill folders are picked up automatically by `home.nix` (`agentSkillsDir`). They must be git-tracked before a flake rebuild.
- `home.nix` activation merges the `sessionStart` hook into `~/.cursor/hooks.json` idempotently with `jq`, preserving the entries other tools write there.
- `vault-seed/` gains the schema pointer, `maps/`, `bases/`, and graph color groups, so the new machine's first rebuild creates a ready vault.

## Tasks

1. Typed-page contract `second-brain/references/typed-pages.md`, `vault.py` loader and validator, and tests.
2. `brief.py` (on-demand and hook mode, once-per-day state in `<vault>/.companion/state.json`) and tests.
3. `second-brain/SKILL.md` update (typed pages, `brief` op) and `vault-seed/` update (schema pointer, index Maps section, `maps/`, `bases/*.base`, `.obsidian/graph.json`).
4. `columbus/scripts/render_maps.py` (world/domain/service/flow/people canvases, layered layout, position preservation, fog nodes, explored %) and tests.
5. `columbus/SKILL.md` with the five modes, evidence rules, and composition with `second-brain`, `repo-navigation`, and `archify`.
6. `home.nix` activation for the idempotent `sessionStart` hook merge.
7. User guide `docs/columbus-guide.md`.
8. Verify: unit tests, render a sample vault, hook dry run, `nix flake check`-level evaluation of `home.nix` if available.

## Out of scope (for now)

Timeline replay of the map, quest log, push notifications, a custom HTML viewer, and Claude Code hook wiring. Add them once the core proves useful.
